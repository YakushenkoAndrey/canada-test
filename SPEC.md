# ТЗ: приложение для подготовки к тесту на гражданство Канады (Discover Canada)

## 1. Цель

Веб-приложение для подготовки к тесту на гражданство Канады. Работает на телефоне и на компьютере, в двух независимых версиях:

- **EN**: официальный оригинал брошюры «Discover Canada: The Rights and Responsibilities of Citizenship»;
- **RU**: мой неофициальный перевод этой же брошюры.

Что умеет приложение:
1. Показывает брошюру поблочно: заголовок, фото, подпись, текст.
2. Озвучивает каждый блок кнопками Play / Pause / Stop и подсвечивает, что звучит сейчас и что уже прочитано.
3. Визуально выделяет ключевые факты, которые вероятно будут в тесте.
4. Даёт тренировочные тесты по главам и пробный экзамен.

Пользователь один (я). Нужны только браузер и ссылка, без серверной части и аккаунтов.

## 2. Входные файлы (лежат в `source/`)

| Файл | Что это |
|---|---|
| `source/discover-canada-en.pdf` | Оригинальная брошюра IRCC на английском |
| `source/discover-canada-ru.pdf` | Русский перевод, свёрстанный PDF (US Letter) |
| `source/ru-text/*.md` или `*.txt` | Исходный текст перевода с разметкой, если он есть |

Также в проекте лежит папка `design/` с утверждённым макетом (см. раздел 7).

Источником правды по тексту считать исходный текст. Если его нет, извлекать текст из PDF. Фото брать из английского PDF (в русском лежат те же самые).

## 3. Технологии

- Статический сайт, без бэкенда. Vite + TypeScript + vanilla JS или Preact: выбери сам, но держи проект простым.
- Сборка в папку `dist/`, которая публикуется на GitHub Pages (см. раздел 8). Собранный сайт должен работать и локально.
- В `vite.config` задать `base` равным имени репозитория (`/canada-test/`), иначе на GitHub Pages не загрузятся стили и картинки.
- Все данные лежат в JSON внутри проекта. Прогресс пользователя хранится в `localStorage`; каждое чтение и запись оборачивать в try/catch.
- Желательно (этап 4): PWA с офлайн-режимом и установкой на телефон.
- Скрипты подготовки данных пишутся на Python и лежат в `tools/`.

## 4. Модель данных

### 4.1 Блоки брошюры: `data/blocks.en.json`, `data/blocks.ru.json`

У обеих версий **одинаковая структура и одинаковые `id`**, чтобы можно было переключить язык в том же месте.

```json
{
  "chapters": [
    {
      "id": "who-we-are",
      "title": "Who We Are",
      "blocks": [
        {
          "id": "who-we-are-03",
          "page": 12,
          "heading": "Aboriginal Peoples",
          "images": [{ "src": "img/p12-1.jpg", "caption": "..." }],
          "paragraphs": [
            "The ancestors of Aboriginal peoples are believed to have migrated from Asia many thousands of years ago. ..."
          ],
          "keyFacts": [
            { "text": "First Nations, Inuit and Métis", "type": "definition" },
            { "text": "1867", "type": "date" }
          ]
        }
      ]
    }
  ]
}
```

- `keyFacts[].text` — это точная подстрока из `paragraphs`. По ней фраза подсвечивается в тексте.
- `type` бывает: `date`, `person`, `number`, `definition`, `place`, `symbol`, `right-duty`.
- В RU-версии ключевой термин сопровождается английским оригиналом в скобках: «Конфедерация (Confederation)». В озвучке английская часть в скобках **не читается** (см. 5.4).

### 4.2 Вопросы: `data/questions.en.json`, `data/questions.ru.json`

```json
{
  "id": "q-who-we-are-007",
  "chapter": "who-we-are",
  "blockId": "who-we-are-03",
  "question": "What are the three main groups of Aboriginal peoples?",
  "options": ["Indians, Inuit, Métis", "First Nations, Inuit, Métis", "Cree, Mohawk, Inuit", "Haida, Dene, Inuit"],
  "answer": 1,
  "explanation": "..."
}
```

- В RU-версии сам вопрос и варианты ответа **на английском**, как на настоящем экзамене, а поле `explanation` на русском. В будущем возможен переключатель «вопросы по-русски», поэтому поля `questionRu` и `optionsRu` можно заполнить сразу.
- Каждый вопрос проверяем по тексту блока `blockId`: ответ должен прямо следовать из брошюры. Никаких фактов извне брошюры, кроме раздела Ontario (см. 6.4).
- Объём: примерно 15–30 вопросов на главу, всего не меньше 250.

## 5. Озвучка (главная фича)

### 5.1 Движок
Web Speech API (`speechSynthesis`), без внешних сервисов.
- Голос выбирается автоматически по языку (`en-CA` → `en-US` → `en-*`; `ru-RU`). В настройках можно выбрать вручную, выбор сохраняется. Учесть, что список голосов загружается асинхронно (`voiceschanged`).
- Скорость: 0.8 / 1.0 / 1.2 / 1.5.

### 5.2 Управление
- Под каждым блоком кнопки **▶ Play**, **⏸ Pause/Resume** и **⏹ Stop**.
- Одновременно звучит только один блок: Play на другом блоке останавливает текущий.
- Режим «Читать дальше»: после конца блока автоматически начинается следующий, страница плавно прокручивается к нему.
- Плавающий мини-плеер внизу экрана: какой блок звучит, пауза/стоп, предыдущий/следующий блок.
- Озвучка включает заголовок и абзацы. Подписи к фото читаются, только если это включено в настройках.

### 5.3 Подсветка
- Текст блока заранее делится на предложения, и каждое предложение отправляется отдельным `SpeechSynthesisUtterance` из очереди. Так подсветка работает надёжно, и обходится известный баг Chrome, когда длинная фраза обрывается примерно через 15 секунд.
- Три состояния текста:
  - **прочитано**: приглушённый цвет;
  - **текущее предложение**: фон-подсветка;
  - **впереди**: обычный текст.
- Подсветка текущего слова по событию `onboundary` (`charIndex`, `charLength`) включается, только если голос шлёт эти события. Если за первое предложение события не пришли, работаем только по предложениям, без ошибок.
- Нажатие на предложение начинает чтение с него.
- Пауза и Resume продолжают с того же места. Если `resume()` в браузере сломан (бывает на Android), повторить текущее предложение.

### 5.4 Подготовка текста к озвучке
- Для RU убирать английские вставки в скобках, ссылки (URL) и номера страниц.
- Сокращения раскрывать по словарю `data/tts-fixes.ru.json` (например, «т. е.» → «то есть», «г.» → «год»). Для EN такой же словарь `data/tts-fixes.en.json`.
- Позиции подсветки считаются по **отображаемому** тексту. Нужна карта соответствия «текст для озвучки → отображаемый текст», чтобы подсветка не съезжала после замен.

### 5.5 Мобильные особенности
- На iOS первая фраза должна запускаться прямо из обработчика нажатия.
- При сворачивании вкладки или блокировке экрана озвучка может прерваться. Это допустимо, но плеер должен корректно показать паузу.

## 6. Ключевые факты и тест

### 6.1 Выделение
- Фразы из `keyFacts` выделяются маркером, цвет зависит от типа (даты, люди, определения…). Легенда цветов в настройках.
- Переключатель **«Только главное»**: каждый блок сворачивается до списка своих ключевых фактов. Режим быстрого повторения.
- Свои пометки: выделил фразу → «★ В избранное». Хранятся в `localStorage`, отдельная страница «Избранное».

### 6.2 Тренировка по главам
- Вопросы по одной главе по одному, после ответа сразу показать правильный вариант, объяснение и ссылку **«Прочитать в брошюре →»**, которая открывает нужный блок с подсветкой.

### 6.3 Пробный экзамен
- 20 случайных вопросов из всех глав, пропорционально объёму глав, проходной балл **15/20**. Таймер 30 минут можно отключить.
- В конце результат, список ошибок с объяснениями и ссылками на блоки.
- История попыток: дата и балл.

### 6.4 Раздел Ontario / Brantford
- Отдельный небольшой набор вопросов: столица провинции, премьер Онтарио, местный депутат (федеральный округ Brantford—Brant) и т. п.
- Эти данные меняются, поэтому при сборке **проверить актуальность по официальным источникам** и указать дату проверки в интерфейсе.

### 6.5 «Мои ошибки»
- Вопросы, на которые я ошибся, попадаются чаще (простая интервальная схема). Отдельная кнопка «Повторить ошибки».

## 7. Интерфейс и дизайн

### 7.1 Утверждённый макет
Макет утверждён и лежит в папке `design/`:

| Файл | Экран |
|---|---|
| `design/Main.dc.html` | Чтение, EN: блок с озвучкой, подсветкой и мини-плеером |
| `design/RU.dc.html` | Чтение, RU: то же, английские термины в скобках |
| `design/KeyFacts.dc.html` | Режим «Только главное» |
| `design/Quiz.dc.html` | Пробный экзамен, экран после ответа |

Это HTML-файлы из дизайн-редактора: разметка с inline-стилями плюс класс `Component` с логикой. Их **не надо запускать**. Читай их как точную спецификацию вида и переноси разметку, стили и поведение в приложение. Логика озвучки из `Main.dc.html` годится как образец: очередь предложений, подсветка слова по `onboundary`, запасной демо-режим, пауза и продолжение.

Главный принцип: приложение должно **выглядеть как оригинальная брошюра**. Если увидишь в `source/discover-canada-en.pdf`, что оформление брошюры отличается от макета (цвет, шрифт, врезки), правь в сторону брошюры и скажи мне об этом.

### 7.2 Визуальный стиль (из макета)
- Шрифты: **PT Sans** для текста и **PT Serif Bold** для названий глав, логотипа и вертикальной полосы. Оба поддерживают кириллицу. Подключить локально (`@fontsource`), без запросов к Google во время работы.
- Цвета:
  - красный брошюры `#B5121B` (заголовки, кнопки, линии), тёмный `#7E0C12` для наведения;
  - текст `#1E1E1E`, вторичный текст `#5C5C5C`, прочитанный текст `#767676`;
  - бежевые врезки `#F5EFE6` с красной полосой 4px сверху;
  - вертикальная полоса справа: фон `#FBF1F0`, надпись «Discover Canada» `#EBC6C2`.
- Подсветка при чтении:
  - текущее предложение: фон `#DCEAFB`;
  - текущее слово: подчёркивание 3px `#1D5FBF`;
  - уже прочитано: `#767676`;
  - ключевой факт: фон `#FADBD8`, текст `#8E1015`, жирный; после прочтения фон `#F6EAE9`, текст `#8F4A45`.
- Цветные метки типов фактов, фон / текст: определение `#E3ECF8`/`#173F78`, право `#E9E3F5`/`#46307A`, место `#E1F0EA`/`#1D5B44`, число и дата `#FBEBD9`/`#7A4210`, народы и люди `#FADBD8`/`#8E1015`.
- Элементы страницы как в брошюре:
  - справа вертикальная полоса шириной 36px с надписью «Discover Canada»;
  - над названием главы строка «Discover Canada · стр. N» заглавными буквами;
  - название главы 38px красным, под ним красная черта 64×4px;
  - фото во всю ширину, подпись курсивом 13px;
  - внизу каждой страницы или главы строка «Your Canadian Citizenship Study Guide» (в RU-версии «Учебное пособие для подготовки к экзамену на гражданство») и номер страницы брошюры.
- Текст брошюры 17px, межстрочный интервал 1.65. Все кнопки не меньше 44px по высоте.

### 7.3 Поведение
- Mobile-first. На компьютере колонка текста шириной до 720px по центру. Светлая тема основная, тёмная по желанию (этап 4).
- Шапка: оглавление, переключатель **EN / RU**, кнопка «Тест».
- Кнопки, меню и подсказки **на русском в обеих версиях**. Английским в EN-версии остаётся только текст брошюры и вопросы теста.
- Под каждым блоком плеер: «Слушать / Пауза / Продолжить», «Стоп», скорость, «Предложение N из M», а под ним легенда цветов подсветки (её можно скрыть в настройках).
- Внизу экрана тёмный мини-плеер с полосой прогресса: название блока, предыдущее и следующее предложение, пауза, стоп.
- При переключении языка открывается тот же блок (по `id`).
- Прогресс чтения: отмечать прослушанные или прочитанные блоки, показывать процент по главам.
- Пометка в подвале RU-версии: «Неофициальный перевод; официальны только английская и французская версии».

## 8. GitHub: репозиторий и публикация

С GitHub я работаю впервые, поэтому всё, что нужно сделать **мне руками** (регистрация, вход, настройки на сайте), объясняй по шагам и коротко, по-русски. Остальное делай сам через `git` и `gh`.

### 8.1 Репозиторий
- Репозиторий на GitHub называется `canada-test`. Его надо создать **в самом начале работы, до первого коммита кода**.
- Проверь, установлены ли `git` и `gh` (GitHub CLI) и выполнен ли вход (`gh auth status`). Если нет, проведи меня через установку и `gh auth login`.
- Видимость **public**: бесплатный GitHub Pages работает только с публичными репозиториями. Ничего личного в репозиторий не класть.
- `.gitignore`: `node_modules/`, `dist/`, временные файлы `tools/`, а также `source/*.pdf`, потому что исходные PDF большие и в сборке не нужны. Извлечённые картинки и JSON-данные **коммитятся**.
- В `README.md`: что это за проект, как запустить локально (`npm install`, `npm run dev`), как пересобрать данные из PDF, ссылка на сайт.

### 8.2 Работа с кодом
- Ветка `main`. Коммиты небольшие, сообщения понятные, по-английски.

- Адрес сайта: `https://<мой-логин>.github.io/canada-test/`. После первой публикации проверь, что он открывается, и дай мне ссылку.

## 9. Этапы

1. **Пилот.** Настройка GitHub (раздел 8), конвейер данных (`tools/`) и одна глава («Who We Are») на двух языках: блоки, фото, озвучка с подсветкой, ключевые факты, 10–15 вопросов. Опубликовать на GitHub Pages, я проверяю на телефоне.
2. **Вся брошюра.** Все главы, ключевые факты и полный банк вопросов.
3. **Тест.** Пробный экзамен, «Мои ошибки», история, раздел Ontario.
4. **Полировка.** PWA и офлайн-режим, «Избранное», настройки голоса.

## 10. Критерии приёмки

- Каждый блок EN и RU озвучивается, Stop мгновенно останавливает речь, подсветка предложения совпадает с тем, что звучит.
- Работает в Chrome на Android, в Safari на iPhone, в Chrome или Edge на Windows.
- Каждый `keyFacts.text` найден в тексте блока. Скрипт `tools/validate.py` проверяет это, а также что `blockId` у каждого вопроса существует и `answer` в допустимом диапазоне.
- В EN и RU одинаковый набор `id` блоков, это тоже проверяет валидатор.
- Нет внешних запросов во время работы, кроме загрузки самого сайта.
- Сайт открывается по адресу GitHub Pages, и каждый пуш в `main` автоматически обновляет его, если сборка прошла.
